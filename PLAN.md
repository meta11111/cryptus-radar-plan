# CRYPTUS — экономный радар тем

Актуальная редакция 2: 15.10.2026. Рабочий план; сервисы ещё не запущены.
Интерактивный документ: work/radar-brief.html; пакет GitHub Pages — work/radar-document-public.

## 1. Цель и режим

Раз в неделю выдавать Никите до 5–8 подходящих тем для контент-плана.
Приоритеты: Reddit → X → Telegram → YouTube. Пилот: 5 проверенных сообществ
Reddit и 10 авторов X. Telegram следующим, YouTube позже; они не блокируют старт.

Предлагаемое расписание: воскресенье 18:00 Europe/Moscow, материалы за последние
7 дней. Первый запуск вручную после получения доступов и проверки лимитов.
Ищем истории, разборы, расследования и полезные обсуждения для следующей недели.
Для срочной новостной ленты такой режим не подходит. Мало достойных тем —
показываем меньше, не дополняем мусором.

Ориентир: $5–10/месяц при доступном кредите Apify Free; со Starter $25–30.
До расходов согласуем. Экономия — в количестве источников,
результатов и обработке. Еженедельный сбор всего недельного потока сам по себе
не делает оплату за публикации дешевле. Сбор статистики своего канала не меняем.

## 2. Схема фильтрации

| Шаг | Действие | Результат |
|---|---|---|
| Проверенные источники | Я проверяю 10–20 последних публикаций каждого кандидата: оригинальность, доказательства, рекламу, шум. Лео подтверждает список. | 5 Reddit + 10 X; ссылка, тема, роль, примеры, правила |
| Дешёвый отсев | Reddit через Apify, X через Grok X Search с разрешёнными авторами; убираем рекламу, розыгрыши, дубли, ценовой флуд, уже использованные сюжеты | До 25 кандидатов: 15 Reddit + 10 X |
| Внешний интерес | Содержательность обсуждения, относительный результат, актуальность, независимое распространение | Оценка 0–100, вклад 45% |
| Ценность CRYPTUS | Аудитория, сюжет/угол, факты, новизна для канала; единая анкета Grok | Оценка 0–100, вклад 55% |
| Редакция → план | До 5–8 карточек; Никита выбирает «В план», «Сохранить», «Не подходит» | Карточка «Идея» со связью с темой; автопубликации нет |

Объём одного выпуска: до 100 Reddit-постов и 40 комментариев у отобранных
публикаций; целевой объём X — до 100 реально полученных постов, включая повторы,
контекст веток и цитаты. Отдельно ограничиваем запросы, max_turns и расходы.
В Grok выключаем поиск профилей, просмотр изображений и видео.

Подробная оценка моделью — только для 25 кандидатов. Сам поиск X также использует
модель и оплачивается до этого отсева. Один запрос может получить больше
предварительно рассчитанного объёма: считаем фактический usage.

Автор и дата X проверяются повторно: thread fetch не использует фильтры
разрешённых авторов и дат. Поиск не гарантирует полный архив и все метрики.
Reddit score — показатель рейтинга, не точное количество положительных голосов.

До 5 из 25 мест оставляем новым содержательным находкам без большой аудитории.
Не запрещаем расследование скама только по слову «скам». Копии одной новости
объединяем, не считаем их независимым подтверждением. Сомнительный факт
показываем как утверждение с оговоркой. Без проверяемого источника в итог не берём.

## 3. Что означает 45 / 55

Это веса оценки темы, не время, бюджет, количество площадок или поиск источников.
Источники выбираем до расчёта. Итог = 0,45 × внешний интерес + 0,55 × польза CRYPTUS.

Внешний блок: обсуждение 35%, относительный результат 30%, актуальность 20%,
независимое распространение 15%. Блок CRYPTUS: аудитория 35%, сюжет/угол 25%,
проверяемая основа 25%, новизна для канала 15%. Каждый критерий — 0–100 с причиной.
Это стартовые гипотезы, а не доказанная вероятность вирусности.

Недоступные признаки не выдумываем. Покрытие c = сумма весов доступных признаков
внешнего блока. При c < 0,5 не считаем точный общий балл; тему можно показать
в отдельных «находках на проверку». Иначе P_obs — средний балл доступных признаков
с их нормированными весами, P = c × P_obs + (1 − c) × 50. Показываем покрытие
и предварительный статус при c < 1. Это защищает от завышения по одной свежести.
Один замер не показывает скорость роста; без истории не утверждаем «выше обычного».

В готовую выдачу: итог ≥65, ценность CRYPTUS ≥60 и проверяемая основа обязательна.
Пример: внешний 80, CRYPTUS 40 → 58, не берём. Внешний 60, CRYPTUS 90 → 76,5,
проходит по баллам. Большой внешний шум не протащит неподходящий сюжет.

## Практические границы реализации фильтра

| Проверка | Вход и точное поведение | Ограничение |
|---|---|---|
| Источник/дата | Разрешённый ID автора/сообщества, настоящий URL/ID, публикация в последних 7 днях | Для X повторять после поиска, включая ветки |
| Дубли | Постоянный ID или каноническая ссылка без рекламных параметров | Повтор обновляет наблюдение, не создаёт карточку |
| Реклама | Явная рубрика/флаг рекламы — исключение; CTA, реферальная ссылка, цена — признаки для смысловой оценки | Не запрещать разбор мошенничества по отдельному слову |
| Разнообразие | До 25 кандидатов: 15 Reddit / 10 X, максимум 5 от одного subreddit и 2 от автора X | До 5 мест первичным находкам; квоты не нужно заполнять |
| Вовлечённость | Сравнение внутри площадки и возрастной группы ≤24h, 24–72h, 72–168h | Минимум 5 сопоставимых постов; иначе признак неизвестен |
| Относительный результат | Baseline своего источника, сопоставимый возраст и метрика | Нужно минимум 10 наблюдений, иначе неизвестен |
| Свежесть | ≤2 суток: 100; ≤4: 80; ≤7: 60 | Это возраст, не скорость роста; потерю смысла за неделю оцениваем отдельно |
| Распространение | Независимые ссылки на событие, подтверждённая связь источников | Перепечатки и цитаты одного источника не независимы; при сомнении неизвестно |
| Сюжет и полезность | Одна анкета Grok на отобранные материалы | Ключевые слова сами по себе не доказывают редакционную ценность |
| Новизна | Точный URL/ID старой темы — сигнал повтора; смысловые кластеры предлагает модель с ID | При сомнении не объединяем разные события; новый факт может пройти |

Перед оценкой выбираем кандидатов по доступным метрикам внутри платформ/возраста,
чередуя источники до их лимитов. При равенстве — более свежие, затем стабильный ID.
Неизвестные показатели не подменяем нулями; такие находки идут в отдельный резерв.
До 5 первичных находок выбираем по разрешённым типам материала и наличию
ссылки/документа, затем по свежести. Качество этой основы ещё должен проверить
редактор/модель: само наличие ссылки не доказывает истинность.

## Нейросеть нужна для смысла, автономный агент не нужен

Рекомендуемый вариант: обычные фильтры + одна ограниченная оценка Grok через тот
же xAI API, который используется для X Search. Отдельный OpenAI API не обязателен.
Покупка и запуск требуют согласования; это рекомендация, не уже подключённый сервис.

Полностью без языковой модели возможен технический отсев, но правила плохо
распознают неожиданный угол, ценность истории и смысловой повтор. Обещание
«только сочные посты» невозможно гарантировать ни с моделью, ни без неё.

Оценщик не имеет инструментов поиска, доступа к секретам и права на публикацию.
Один основной пакет до 25 кандидатов, максимум 2000 символов на пост плюс
ограниченные комментарии; одна повторная попытка только при сбое. Сам поиск X —
отдельная ограниченная операция, а не бесконечный агентский цикл.

Анкета фиксирована и версионируется. По четырём критериям CRYPTUS модель выдаёт
оценки 0–4 с причиной и использованными входными ID; затем код переводит в 0–100
по весам. 0 — признак отсутствует/неподходяще, 1 — слабый, 2 — частичный,
3 — явный и полезный, 4 — сильный и конкретно обоснованный переданным материалом.
Статус фактов: «утверждение автора», «поддержано переданным материалом»,
«нужна проверка». Это не независимый фактчекинг всего интернета.

Ответ по схеме: candidate_id, оценки критериев, короткая причина, supporting_item_ids,
список утверждений со статусом и предложения группировки по существующим ID.
В коде валидируем ID, диапазоны, обязательные поля; URL/метрики/цитаты принимаем
только из входа. Тексты постов трактуются как данные, не инструкции.
Кэш по hash содержимого + версии модели/анкеты исключает повторную оценку
неизменённых материалов; обновление статистики пересчитывает числовой блок
без повторного смыслового запроса.

При ошибке модельной части после повтора показываем кандидатов со статусом
«смысловая оценка не выполнена», не выдаём их за готовые рекомендации.
[Структурированные ответы Grok](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)
позволяют задать схему, но не гарантируют истинность ответа.

## 4. Настройка без нагрузки на Лео

1. Я готовлю анкету и список по ТЗ, описанию аудитории и публикациям CRYPTUS.
2. Лео подтверждает 3 хороших и 2 плохих примера с одной фразой «почему».
   Если неудобно искать — я подбираю сам, он только поправляет.
3. Никита принимает обычные решения. Причина отказа необязательна; пропуск
   темы не считается отрицательной оценкой, перенос в план — положительный сигнал.
4. После двух подборок проверяем качество и вручную корректируем источники
   и анкету. Разметка 30–50 внешних тем, fine-tuning и отдельный агент не нужны.
5. В дальнейшем связываем опубликованную тему с настоящими 24h-результатами.
   Из поздней статистики не восстанавливаем выдуманный суточный замер.

При недоступном Free и необходимости начать немедленно резервный сценарий:

и не загружаем все ветки. Проверяем, что реальная тарификация соответствует лимитам.

## 7. Реализация и проверка

1. Каталог источников и анкета → короткое подтверждение Лео.
2. Ограниченный сбор → настоящие ссылки, наличие показателей, реальная стоимость.
3. Отдельные таблицы источников, сигналов, тем, оценок, решений в Supabase.
   Текущий приёмник статистики не меняем; секреты только на сервере, RLS для команды.
4. Экран «Радар» → перенос с nullable radar_topic_id в контент-план;
   модель возвращает признаки, причины, ссылки и покрытие доступных данных.
5. Две недельные подборки: минимум 6 из первых 10 рекомендаций подходят,
   минимум 3 темы в неделю берутся в работу. Это критерий, не обещание результата.

Проверяем: whitelist для авторов из веток, дубли, рекламу, полезные маленькие
находки, неизвестные метрики, отсутствие точного балла без данных, связь с планом,
повтор без дублирования. Сбой одной площадки виден и не блокирует остальные;
одна повторная попытка неудавшейся части. При нехватке бюджета не стартуем задачу.
